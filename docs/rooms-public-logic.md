# منطق الغرف العامة

## 1. الهدف

تتيح الغرف العامة للاعب أن يرى الغرف المفتوحة للانضمام مباشرة من دون إدخال رمز الغرفة. تبقى الغرف الخاصة والانضمام بالرمز متاحين كما هما؛ جعل الغرفة عامة هو خيار صريح من شاشة إنشاء الغرفة.

التنفيذ الحالي موجود أساسًا في:

- `js/online.js`: حالة الغرفة، شاشة القائمة، الإنشاء، الانضمام، العدادات، والتبليغ.
- `supabase/migrations/20260927000000_public_rooms.sql`: أعمدة الغرف العامة وجدول البلاغات والفهرس.
- `ONLINE-MULTIPLAYER-TEST.md`: حالات الاختبار M29–M33.

لا يحتاج تدفق الغرف العامة إلى تعديل `index.html`، ولا يغيّر منطق التسجيل أو التحقق أو القاموس.

---

## 2. النموذج المعماري

المشروع موقع ثابت؛ لا توجد طبقة Backend خاصة بالغرف العامة. المتصفح يتصل مباشرةً بـ Supabase باستخدام عميل JavaScript الموجود في `online.js`.

```text
المستخدم
   |
   v
online.js
   |-- إنشاء غرفة عامة --------> rooms
   |-- تحميل القائمة ----------> rooms + players
   |-- الانضمام من القائمة ----> players
   |-- الإبلاغ -----------------> room_reports
   |
   `-- تحديث القائمة كل 3 ثوانٍ عبر polling
```

### مبادئ مهمة

1. **الغرفة العامة اختيارية**: القيمة الافتراضية هي غرفة خاصة.
2. **لا توجد قائمة منفصلة للغرف**: تُقرأ الغرف من جدول `rooms` نفسه.
3. **لا توجد خدمة إشراف آلية**: البلاغ يسجل صفًا فقط، ولا يحذف الغرفة ولا يخفيها تلقائيًا بسبب عدد البلاغات.
4. **تُستخدم آلية الانضمام الحالية**: الانضمام من القائمة يمر عبر `joinRoom(roomId)` بدل نسخ منطق الانضمام.
5. **Polling بدل Broadcast**: تُحدّث شاشة القائمة كل 3 ثوانٍ، ولا تُستخدم قناة Supabase Broadcast جديدة.

---

## 3. بيانات الغرفة العامة

يُضاف إلى `rooms`:

| الحقل | النوع | المعنى |
|---|---|---|
| `is_public` | `boolean` | يحدد هل تظهر الغرفة في القائمة العامة. القيمة الافتراضية `false`. |
| `room_name` | `text` nullable | الاسم الظاهر في القائمة العامة. مطلوب عمليًا عند اختيار الغرفة العامة، وليس للغرف الخاصة. |

Migration الحالية:

```sql
ALTER TABLE rooms
  ADD COLUMN IF NOT EXISTS is_public boolean NOT NULL DEFAULT false,
  ADD COLUMN IF NOT EXISTS room_name text;

CREATE INDEX IF NOT EXISTS rooms_public_waiting_created_idx
  ON rooms (is_public, status, created_at DESC);
```

الفهرس يطابق نمط القراءة الرئيسي: الغرف العامة التي حالتها `waiting` مرتبة من الأحدث إلى الأقدم.

---

## 4. جدول البلاغات

يُستخدم جدول `room_reports` لتسجيل البلاغات للمراجعة البشرية لاحقًا:

| الحقل | النوع | المعنى |
|---|---|---|
| `id` | `uuid` | المعرّف الأساسي، يُنشأ تلقائيًا. |
| `room_id` | `uuid` | الغرفة المُبلّغ عنها، مع مرجع إلى `rooms`. |
| `reported_by` | `uuid` nullable | اللاعب الذي أرسل البلاغ، أو `null` إذا لم توجد هوية لاعب متاحة. |
| `created_at` | `timestamptz` | وقت تسجيل البلاغ. |

يوجد قيد فريد على الزوج:

```sql
UNIQUE (room_id, reported_by)
```

لذلك لا يُسجل اللاعب نفسه أكثر من مرة للغرفة نفسها. تعالج الواجهة خطأ التكرار `23505` كحالة نجاح وظيفية، وتعرض أن البلاغ سُجل بالفعل.

> البلاغ لا يسبب حذف الغرفة، ولا يخفيها، ولا يحسب عتبة تلقائية، ولا يغير حالة `rooms`.

## 5. حالة الوحدة الداخلية

تحفظ الوحدة حالتها في الكائن `o` داخل `online.js`:

```js
settings: {
  totalRounds: 3,
  roundDuration: 60,
  isPublic: false,
  roomName: ""
}
```

وتستخدم أيضًا:

- `publicPollId`: معرّف مؤقت تحديث قائمة الغرف.
- `publicLoading`: يمنع بدء تحميل جديد قبل انتهاء التحميل الحالي.
- `reporting`: كائن يمنع إرسال بلاغات متكررة للغرفة نفسها أثناء الطلب.
- `joining`: يحمي مساري الانضمام بالرمز والانضمام من القائمة معًا.

تُصفّر هذه القيم عند الخروج عبر `cleanup()` أو عند مغادرة شاشة الغرف العامة.

## 6. تدفق إنشاء غرفة عامة

### 6.1 فتح شاشة الإنشاء

من `onlineMenu` يختار اللاعب **إنشاء غرفة**. شاشة الإنشاء تعرض اختيارًا بين:

- **خاصة**: مفعلة افتراضيًا.
- **عامة**: تفتح حقل اسم الغرفة العامة.

عند الرجوع إلى شاشة الإنشاء تُعاد القيم إلى:

```js
o.settings.isPublic = false;
o.settings.roomName = "";
```

وهذا يمنع تحويل غرفة خاصة إلى عامة بسبب قيمة قديمة من محاولة سابقة.

### 6.2 التحقق

عند الضغط على إنشاء:

1. يجب أن يكون اسم اللاعب بطول حرفين على الأقل.
2. إذا كانت الغرفة خاصة، لا يلزم اسم غرفة عامة.
3. إذا كانت الغرفة عامة، يجب أن يكون `roomName` بين حرفين و40 حرفًا.
4. يمر اسم الغرفة عبر `normalizeArabic()` ثم يُقارن بقائمة حظر عربية وإنجليزية صغيرة.
5. عند الرفض تظهر رسالة لطيفة:

```text
الاسم يحتاج تعديل بسيط، جربي صياغة ثانية.
```

الفلتر **ليس ضمانًا شاملاً**؛ فهو لا يغطي بالضرورة المسافات بين الحروف أو الاستبدالات الرقمية أو كل طرق التحايل.

### 6.3 الإدراج

تُنشأ الغرفة بإدراج واحد في `rooms`:

```js
{
  id: roomId,
  code: roomCode,
  host_id: meId,
  status: "waiting",
  total_rounds: o.settings.totalRounds,
  round_duration: o.settings.roundDuration,
  current_round: 0,
  is_public: o.settings.isPublic,
  room_name: o.settings.isPublic ? o.settings.roomName : null
}
```

بعد إنشاء صف الغرفة يُدرج المضيف في `players`، ثم تُحفظ الجلسة وتبدأ Realtime وتُعرض غرفة الانتظار.

## 7. تدفق شاشة الغرف العامة

### 7.1 الوصول

من قائمة اللعب أونلاين يضغط اللاعب **غرف عامة**، فتنتقل الحالة إلى:

```text
onlinePublicRooms
```

وتحتوي الشاشة على:

- حقل اسم اللاعب، المطلوب عند الانضمام.
- قائمة الغرف العامة.
- زر **انضمام برمز** كمسار بديل.
- زر **رجوع** إلى القائمة الأونلاين.

### 7.2 استعلام الغرف

تطلب `loadPublicRooms()` أحدث 30 غرفة مطابقة:

```js
client.from("rooms")
  .select("id,room_name,created_at,status")
  .eq("is_public", true)
  .eq("status", "waiting")
  .order("created_at", { ascending: false })
  .limit(30)
```

لا تُعرض الغرف التي بدأت اللعب أو الغرف الخاصة.

### 7.3 حساب عدد اللاعبين

بعد الحصول على الغرف، تجمع الوحدة معرّفاتها في استعلام واحد:

```js
client.from("players")
  .select("room_id")
  .in("room_id", ids)
  .is("kicked_at", null)
```

ثم تبني `countByRoom` في الذاكرة. هذا يمنع نمط N+1 الذي كان سيصدر استعلامًا منفصلًا لكل غرفة.

### 7.4 العرض

لكل غرفة يظهر:

- اسم الغرفة.
- العدد بصيغة `العدد / 6`.
- الحالة `مفتوحة` أو `ممتلئة`.
- زر الانضمام إذا كان العدد أقل من 6.
- زر **إبلاغ عن الغرفة**.

إذا كان العدد 6 أو أكثر، يُعطل زر الانضمام وتظهر الحالة `ممتلئة`.

### 7.5 التحديث

تبدأ الشاشة طلبًا أوليًا ثم تضبط polling كل 3 ثوانٍ:

```js
loadPublicRooms();
o.publicPollId = setInterval(loadPublicRooms, 3000);
```

يمنع `publicLoading` تداخل طلبين متزامنين. عند الانتقال إلى شاشة أخرى يُلغى المؤقت عبر `route()` أو `clearTimers()`.

## 8. تنظيف الغرف القديمة

عند تحميل القائمة، تفحص الوحدة الغرف المنتظرة التي مضى على إنشائها أكثر من ساعتين. عند العثور عليها:

1. تحدّث `is_public` إلى `false`.
2. تحذفها من القائمة الحالية قبل عرضها.

هذا حل انتهازي من جهة العميل لأن المشروع لا يعتمد حاليًا على وظيفة جدولة مضمونة لتنظيف الغرف القديمة.

```js
await client.from("rooms")
  .update({ is_public: false })
  .in("id", stale)
  .eq("status", "waiting");
```

لا يُطبّق هذا التنظيف على الغرف التي بدأت اللعب، ولا يحذف صف الغرفة من قاعدة البيانات.

## 9. الانضمام من القائمة

عند الضغط على زر الانضمام، تستدعي الواجهة:

```js
joinRoom(roomId)
```

وتختار اسم اللاعب من الحقل `opName`. لا يُطلب رمز غرفة.

### خطوات `joinRoom(roomId)`

1. فحص `o.joining` لمنع النقر المكرر.
2. التحقق من اسم اللاعب.
3. قراءة الغرفة باستخدام `id` مع شرط `status = 'waiting'`.
4. عد اللاعبين النشطين فقط، أي الصفوف التي `kicked_at IS NULL`.
5. رفض الانضمام عند بلوغ `MAX_ONLINE_PLAYERS = 6`.
6. إدراج لاعب جديد في `players`.
7. حفظ الغرفة واللاعب في `o.room` و`o.me`.
8. حفظ جلسة الاستئناف.
9. تشغيل Realtime والانتقال إلى غرفة الانتظار.

مسار الانضمام بالرمز يستخدم الدالة نفسها، لكنه يبحث عن الغرفة بواسطة `code` بدل `id`. هذا يحافظ على سلوك موحد ويمنع تكرار منطق الإدراج والحماية من السباق.

> يوجد فحص سعة قبل الإدراج، لكنه ليس معاملة ذرية على مستوى قاعدة البيانات؛ لذلك يظل الاختبار متعدد الأجهزة مهمًا للتحقق من سلوك السباق.

---

## 10. الإبلاغ عن غرفة

زر الإبلاغ مرتبط بكل صف في القائمة. عند الضغط:

1. يُفحص `o.reporting[roomId]` لمنع إرسال طلبين متزامنين.
2. يُعطل الزر أثناء الطلب.
3. يُدرج صف في `room_reports`:

```js
{
  room_id: roomId,
  reported_by: o.me ? o.me.id : null
}
```

4. عند النجاح يتحول الزر إلى **تم تسجيل البلاغ**.
5. عند الخطأ غير خطأ القيد الفريد `23505` يُعاد تفعيل الزر وتظهر رسالة فشل.
6. لا تتغير قائمة الغرف بسبب البلاغ.

لا يوجد في العميل:

- عدّاد للبلاغات.
- حد بلاغات لإخفاء الغرفة.
- حذف تلقائي.
- حظر تلقائي.
- ترتيب حسب عدد البلاغات.

## 11. نقاط الأمان والصحة

### ترميز المخرجات

تُمرر أسماء الغرف ومعرّفاتها إلى `esc()` قبل إدراجها في HTML. هذا ضروري لأن اسم الغرفة إدخال يسيطر عليه المستخدم.

### حدود الإدخال

- اسم اللاعب: يطبق حد الحقل الموجود في الواجهة والتحقق الأدنى.
- اسم الغرفة: من حرفين إلى 40 حرفًا.
- قائمة الغرف: 30 غرفة كحد أقصى.
- عدد اللاعبين: 6 كحد أعلى.

### الجلسة المجهولة

اللاعبون مجهولو الهوية ويستخدم كل متصفح معرّفًا محليًا مؤقتًا. لا توفر الغرف العامة نظام حسابات أو ملكية دائمة. لذلك:

- لا يمكن اعتبار البلاغ هوية قانونية أو موثوقة.
- منع اللاعب المطرود يعتمد على صف الجلسة الحالي، وليس حظر جهاز دائمًا.
- لا ينبغي إضافة حظر IP أو بصمة جهاز إلى هذا التدفق دون قرار معماري مستقل.

### صلاحيات قاعدة البيانات

يجب أن تكون سياسات Supabase متوافقة مع القراءة والإدراج والتحديث المطلوبين. خصوصًا:

- قراءة الغرف العامة واللاعبين اللازمة للقائمة.
- إدراج لاعب جديد في `players`.
- إدراج البلاغ في `room_reports`.
- عدم إضافة سياسة `SELECT` خاصة بالبلاغات العامة لمجرد عرض القائمة؛ البلاغات تُراجع إداريًا لاحقًا.

## 12. حالات الفشل المتوقعة

| الحالة | السلوك المتوقع |
|---|---|
| فشل تحميل الغرف | تظهر رسالة تعذر تحميل الغرف العامة. |
| فشل تحميل اللاعبين | تظهر رسالة تعذر تحميل اللاعبين. |
| لا توجد غرف | تظهر رسالة لا توجد غرف عامة مفتوحة الآن. |
| الغرفة بدأت أثناء العرض | يفشل استعلام الانضمام وتعود رسالة أن الغرفة غير متاحة أو بدأت. |
| الغرفة امتلأت أثناء الانضمام | يرفض الطلب برسالة حد 6 لاعبين. |
| اسم عام قصير أو طويل | تظهر رسالة تحقق داخل شاشة الإنشاء. |
| اسم عام محظور | تظهر رسالة التعديل اللطيفة دون إنشاء الغرفة. |
| بلاغ مكرر | يعامل كبلاغ مسجل، ولا تظهر مشكلة للمستخدم. |
| ضغط متكرر على الانضمام | يمنعه `o.joining`. |
| طلبا تحميل متزامنان | يمنعهما `o.publicLoading`. |

## 13. خطة الاختبار

يجب تنفيذ الاختبار على جهازين أو متصفحين مستقلين، وليس تبويبين يشتركان بالضرورة في الحالة نفسها.

| المعرّف | السيناريو | النتيجة المتوقعة |
|---|---|---|
| M29 | إنشاء غرفة عامة من الجهاز A وفتح القائمة من B | تظهر الغرفة خلال ثوانٍ مع اسمها وعدد لاعبيها الصحيح. |
| M30 | محاولة إنشاء اسم محظور | يُرفض الإنشاء برسالة لطيفة ولا يُعدّل الاسم تلقائيًا. |
| M31 | الإبلاغ عن غرفة ثم تكرار الضغط | يُسجل صف واحد فقط ولا تختفي الغرفة. |
| M32 | ملء غرفة عامة إلى 6/6 | تظهر `ممتلئة` ويُعطل زر الانضمام. |
| M33 | الانضمام من القائمة ثم بالرمز | يعمل المساران ويصلان إلى حالة غرفة الانتظار نفسها. |

فحص سريع محلي:

```bash
node --check js/online.js
bash tests/online-preflight.sh
git diff --check
```

فحص قاعدة البيانات بعد الاختبار:

```sql
select id, room_name, is_public, status, created_at
from rooms
where is_public = true
order by created_at desc
limit 30;
```

```sql
select room_id, reported_by, created_at
from room_reports
order by created_at desc
limit 20;
```

## 14. قرارات خارج النطاق

هذه الوظائف غير موجودة عمدًا في منطق الغرف العامة الحالي:

- البحث أو التصفية باسم الغرفة.
- Pagination متقدم.
- وضع المتفرج.
- تحقيق أو إشراف آلي.
- إزالة الغرفة بناءً على عدد البلاغات.
- جدولة خادم مؤكدة لتنظيف الغرف القديمة.
- حظر دائم للاعبين أو الحسابات.

أي إضافة لهذه الوظائف يجب أن تكون تغييرًا منفصلًا مع مواصفة واختبارات خاصة بها.
